# Сканер Вливаний — README

Telegram-бот на Python, который сканирует бессрочные фьючерсы Bybit и подсвечивает
лонг-сетапы по притоку денег (Open Interest + объём). **Бот не торгует сам** —
только показывает, комментирует и ведёт позицию после того, как ты нажал «Я вошёл».

---

## 1. Философия в двух словах

- **Read-only.** Все обращения к Bybit — публичный REST без ключей и без аккаунта
  (`/v5/market/kline`, `/v5/market/open-interest`, `/v5/market/tickers` и т.п.).
  Единственный секрет во всём проекте — токен Telegram-бота.
- **Подсветка, не приказ.** Каждая карточка сигнала заканчивается напоминанием,
  что решение и риск — на трейдере. Комментарии бота описывают текущее состояние,
  а не предсказывают будущее.
- **Честная самопроверка вместо самообмана.** Бот логирует каждый отправленный
  сигнал и каждую закрытую сделку, чтобы можно было измерить реальный результат
  (`/stats`, `/backtest`, `/btcstats`) — включая сравнение с «просто держать BTC».
  Если сигналы не обгоняют это — это не эдж, а рыночная бета.

## 2. Быстрый старт (деплой на Railway)

### Обязательно

| Что | Зачем |
|---|---|
| `TG_TOKEN` (переменная окружения) | Без неё процесс зависает на `input()` — на сервере это значит, что бот просто не поднимется. |
| Volume, примонтированный на `/data` | Без него `POSITIONS`/`WATCH`/журналы не переживут рестарт. См. п. 5. |
| Регион деплоя, откуда доступен Bybit | Bybit блокирует часть регионов. Проверяется командой `/bybit` сразу после деплоя. |

### Переменные окружения (все опциональны, дефолты уже указывают на `/data`)

```
TRADES_FILE     = /data/scanner_trades.csv
CHAT_FILE       = /data/scanner_chat.txt
SIGNALS_FILE    = /data/scanner_signals.csv
BLOCKS_FILE     = /data/scanner_blocks.csv
STATE_DB        = /data/scanner_state.db
HISTORY_FILE    = /data/scanner_history.csv
```

Переопределять есть смысл только если несколько инстансов бота делят один volume.

### Проверочный чек-лист после деплоя

1. `/bybit` — доступен ли Bybit из этого региона.
2. Первое сообщение от бота после старта — автоматический `startup_selfcheck()`:
   либо «✅ Персистентность ОК», либо явное предупреждение, что `/data` недоступен
   для записи.
3. `/start`, потом ручной рестарт сервиса — чат и открытые позиции должны пережить
   рестарт.

Никаких pip-зависимостей сверх обычных (`requests`, `numpy`) — `sqlite3` встроен
в Python.

## 3. Команды

| Команда | Что делает |
|---|---|
| `/start` | Регистрирует чат, показывает список команд. |
| `/scan` | Ручной скан прямо сейчас (авто-скан и так идёт каждые `SCAN_EVERY_MIN` минут). |
| `/pos` | Список открытых позиций. |
| `/watch` | Кого сейчас отслеживает (ретест зоны, ожидание пробоя треугольника и т.п.). |
| `/log` | Журнал закрытых сделок (csv-файл). |
| `/stats` | Форвардная статистика по отправленным сигналам + бенчмарк против BTC. |
| `/backtest [часы] [дни]` | Бэктест на собственном архиве `HISTORY_FILE` (по умолчанию 24ч/30дн). См. п. 8. |
| `/btcstats` | Проверка самого BTC-рубильника: оправданы ли были блокировки лонгов. |
| `/bybit` | Диагностика доступа к Bybit API из текущего региона. |

Кнопки под карточками сигналов: **✅ Я вошёл** (начать вести позицию) и
**❌ Выйти / зафиксировать** (закрыть и записать в журнал).

## 4. Как устроена стратегия

### 4.1 Сканирующий цикл

Каждые `SCAN_EVERY_MIN` минут бот проходит до `MAX_COINS` монет, тянет часовые
свечи + Open Interest, считает единый набор метрик (`core()`), и решает по
очереди: обычный лонг → треугольник → ранний 15м-сигнал → разворотный сигнал →
ранний сигнал по сжатию. Максимум `MAX_ALERTS` карточек за цикл.

Перед этим — два **рубильника**, которые могут остановить вообще все новые
сигналы на цикл:
- **BTC-рубильник**: если у самого BTC ≥2 из 6 медвежьих признаков (обвал за 1ч,
  падение за 4ч, отток OI, тренд вниз, объём на падении, перепроданность) —
  новые лонги по альтам блокируются.
- **Дневной лимит убытка**: если сумма % по сделкам, закрытым сегодня, ≤ −5% —
  новые сигналы приостановлены до следующего дня. Открытые позиции продолжают
  вестись как обычно — это не общий стоп, а пауза именно на новые входы.

### 4.2 Основной ЛОНГ-сигнал

Два пути входа:
- **Быстрый**: OI +2% за 1ч (`OI_1H_MIN`) + объём последних 1-2 свечей ≥2x
  (`SPIKE_FAST_MIN`) — ловит движение почти сразу, не дожидаясь 4ч-картины.
- **Обычный**: OI +5% за 4ч (`OI_4H_MIN`) + объём 4ч ≥1.5x (`VOL_SPIKE_MIN`).

Дальше — общие условия: тренд вверх (цена и EMA21 выше EMA50), не падающий нож
(не более −40% от 7-дневного хая), ликвидность от $30M/сутки, RSI ≤78, рынок не
в чопе (ATR не ниже 60% нормы), спред и funding в разумных пределах.

**Ворота «поздно»** — сигнал НЕ шлётся, если:
- цена больше чем на 8% выше EMA21 (`MAX_EXT_ENTRY`), или
- цена выросла больше чем на 10% за 4ч (`MAX_MOVE_4H`), или
- **последняя часовая свеча — резкий разовый скачок** (`spike_guard`, диапазон
  свечи ≥2.5x типичного за 20ч): ловит быстрый V-скачок, который первые два
  порога пропускают, потому что он ещё не успел набрать 8%/10% по медленным
  метрикам.

В тихие часы (0-6 UTC, выходные) пороги объёма домножаются на `NIGHT_VOL_MULT`
(1.3) — ночью база объёма ниже, и без поправки относительный всплеск обманчив.

### 4.3 Точка входа и ретест

Карточка лонга всегда пишет: «не по рынку сейчас, вход только на ретесте» — и
это подкреплено реальным механизмом (`WATCH`), а не пустым обещанием: бот сам
следит за зоной отката (EMA21 / база консолидации, либо ближайший сильный
уровень, либо крышка треугольника при пробое) и присылает отдельное сообщение,
когда цена туда вернулась и отбилась.

### 4.4 Остальные типы сигналов

| Тип | Суть | Особенность |
|---|---|---|
| **Треугольник** | Сужающийся диапазон: плоская крышка + растущее дно. Стадии `ready`/`breakout`. | На стадии `ready` бот ставит монету на активное ожидание пробоя — проверяется отдельно каждые 15с (`check_tri_alert`), не только на общих основаниях. |
| **Разворот** (экспериментальный) | Даунтренд → нет новых минимумов → устойчивый всплеск объёма на зелёной свече → рост OI (фильтр от шорт-сквиза). | Двухстадийный: сетап найден → ждём подтверждения закрытием следующей свечи выше триггера, только потом шлём карточку. |
| **Ранний 15м** (экспериментальный) | Движение только началось — объёмный всплеск на 15м + 3 зелёные свечи подряд. | Явно помечен как радар, не команда входа — подтверждение приходит позже часовым сигналом. |
| **Ранний по сжатию** (экспериментальный) | Пробой из зоны компрессии (диапазон заметно ýже нормы) на объёме. | Тоже не подтверждённый сетап — предварительный сигнал. |

Экспериментальные типы логируются в статистику отдельно от основного лонга,
чтобы не смешивать разную по природе статистику.

## 5. Сопровождение позиции (выход)

После «✅ Я вошёл» бот проверяет позицию каждые `CHECK_POS_MIN` минут и
классифицирует её в одно из состояний (по приоритету сверху вниз, каждое
шлётся один раз при переходе в него, не спамит на каждой проверке):

1. **`reversal`** — OI резко упал (≥3% за 1ч) или цена ушла ниже EMA50. Самый
   срочный сигнал.
2. **`drawdown`** — убыток ≥1R (R = ATR14×1.5 на момент входа), но формально не
   задел ни OI, ни EMA50. Не «разворот» по узким правилам, но и не повод для
   бодрого «всё ок».
3. **`take_partial`** — RSI ≥82 при прибыли: классический повод подумать о
   частичной фиксации, резкие откаты от такого перегрева обычны.
4. **`trail_stop`** — прибыль ≥1R: есть что защищать, пора двигать стоп хотя бы
   в безубыток.
5. **`stalled`** — открыта ≥20ч, а P&L топчется в пределах ±1.5%: тезис явно не
   разворачивается быстро.
6. **`ok`** — ничего особенного, периодическое спокойное обновление раз в
   `CALM_UPDATE_MIN` минут.

В карточке входа теперь есть не только карта стопов (кластеры ликвидаций,
перекос лонг/шорт, «умный стоп» за кластером), но и **лестница целей** (1R/2R/3R
+ ближайший уровень/7-дневный хай над ценой) и **пример сайзинга** — бот не
знает размер депозита, поэтому это формула с иллюстративным числом.

## 6. Портфельный риск

Ничего не блокирует молча (кроме дневного лимита убытка, см. 4.1) — только
делает риск видимым в карточке:

- предупреждение, если уже открыто ≥`MAX_CONCURRENT_POS` (6) позиций;
- предупреждение о скрытой концентрации: если новая монета сильно коррелирует
  с BTC (≥`PORTFOLIO_HI_CORR`, 75%) и среди уже открытых позиций тоже есть
  высоко-бета монеты — несколько «разных» монет могут быть одной плечевой
  ставкой на BTC в нескольких обёртках.

## 7. Персистентность и надёжность

- **`STATE_DB`** (sqlite) — `POSITIONS`, `WATCH`, ожидания пробоя треугольника
  и все кулдауны переживают рестарт/передеплой. Сбрасывается на диск каждые
  `STATE_FLUSH_SEC` секунд + сразу при входе/выходе из позиции.
- **`startup_selfcheck()`** — при каждом старте бот сам пишет тестовую запись в
  `STATE_DB`, читает её обратно новым соединением и говорит результат в лог и
  в Telegram. Не нужно руками проверять через SSH.
- **Heartbeat** — раз в `HEARTBEAT_EVERY_H` часов бот сам присылает статус
  (сколько позиций, сколько на отслеживании, P&L за день). Тишина сама по себе
  — уже сигнал, что что-то не так.
- **Уведомление о сбое** — если главный цикл ловит исключение, шлётся алерт в
  Telegram (не чаще раза в 10 минут), а не только запись в лог, который никто
  не читает в реальном времени.

## 8. Бэктест

`HISTORY_FILE` копится с каждого скана — метрики по **каждой** отсканированной
монете (не только тем, что дали сигнал), включая `long_ok` (прошла бы фильтр
или нет) и цену BTC в тот момент.

`/backtest [часы] [дни]` сравнивает форвардный результат монет, которые фильтр
пропустил бы, против тех, что отсеял бы, и обе группы — против BTC за то же
окно.

**Важно:** архив пишется только вперёд с момента добавления этой функции —
задним числом данных нет и быть не может (публичный REST Bybit хранит историю
Open Interest ограниченное время, точную цифру биржа не публикует). При малой
выборке (`n<50`) бот сам об этом честно предупреждает — это не «плохой
результат», а рано мерить.

## 9. Известные ограничения (честно, а не для галочки)

- **Пороги — экспертная эвристика, не откалиброванные по реальным данным
  величины.** `MAX_EXT_ENTRY`, `spike_guard`'s 2.5x, `RSI_TAKE_PARTIAL`,
  `TRAIL_TRIGGER_R` и т.п. — разумные, проверенные на синтетике и на
  конкретных живых случаях числа, но не результат бэктеста на истории. Правильно
  откалибровать их сможет только `/backtest` на реальных накопленных данных.
- **Эдж по направлению не измерен и не гарантирован.** Инструмент проверяет
  себя честно (`/stats`, `/backtest`), но по состоянию на данный момент выборка
  ещё маленькая. Механически корректный вход — не то же самое, что прибыльная
  стратегия.
- **Карта стопов — оценка, не факт.** Публичный REST Bybit не даёт данных по
  реальным ликвидациям, зоны считаются через типовое плечо (10x/25x), как это
  делают публичные агрегаторы (CoinGlass и т.п.).
- **Один источник данных.** Все метрики — только с Bybit. Для топовых монет
  разница с рынком в целом небольшая, для мелких альтов приток объёма/OI на
  одной бирже может не отражать полную картину.

## 10. Чего в боте НЕТ (и почему)

**Автоматического исполнения ордеров нет.** Бот нигде не размещает ордера —
только читает публичные данные и присылает уведомления. Это не забытая
функция, а осознанная граница: правильная инженерная последовательность —
сначала подтвердить эдж на бэктесте, потом проверить исполнение на paper
trading без реальных денег, и только потом — ограниченный live с жёсткими
лимитами. Когда/если до этого дойдёт, туда войдут: аутентификация к приватному
API, расчёт размера позиции, реальная постановка стоп/тейк ордеров вместо цены
в тексте карточки, обработка частичных исполнений и защита от задвоенных
ордеров при рестарте — отдельный, целенаправленный этап разработки.
